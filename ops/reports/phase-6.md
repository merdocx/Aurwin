# Отчёт по фазе 6 «Сознание»

Дата: 2026-07-31

С этой фазы начинаются реальные траты по ключу Anthropic API (CLAUDE.md,
«Незыблемые правила», п.7 — рефлексия была замокана до сих пор).
`ANTHROPIC_API_KEY` в `.env` этой среды оказался реальным рабочим ключом —
поэтому, помимо обязательного тестового гейта (фейковый транспорт, $0
реальных затрат), сделан и живой боевой прогон против настоящего Anthropic
API на уже работающем мире (см. «Фактическая стоимость» ниже).

## Что сделано

### Обязательные артефакты (все присутствуют)

- `services/reflection-worker/src/queue.ts` — отбор кандидатов: дебаунс (4ч
  событийная / 24ч фоновая, реализован в SQL по истории `reflections` —
  переживает рестарт процесса воркера), слияние ВСЕХ непоглощённых
  эпизодов существа в один вызов, двухуровневый глобальный лимит событийных
  (30/час И 120/сутки, FIFO по самому старому ожидающему эпизоду при
  нехватке бюджета).
- `services/reflection-worker/src/anthropic.ts` — клиент Anthropic API:
  обычный вызов Messages API для событийной рефлексии (Sonnet), Batch API
  (создание + опрос) для фоновой (Haiku), промпт-кэширование системного
  блока (`cache_control: ephemeral`), учёт стоимости/латентности через
  `recordLlmCall` (metrics.ts). Модели читаются из `config/constants.yaml`
  (`reflection.models`), нигде не хардкожены.
- `services/reflection-worker/src/validate.ts` — валидация выхода по А.5:
  JSON-схема (со снятием markdown-обёртки), длина narrative (≤150 слов),
  диапазоны дельт черт (±0.1) и весов (±0.05), белый список эффектов
  намерений и путей весов, резолв ссылок на существ ТОЛЬКО по именам,
  реально присутствовавшим во входных данных запроса (7.8.6/А.5), плюс
  эвристическая проверка честности повествования (`findUngroundedNames`).
- `services/reflection-worker/src/apply.ts` — дельты черт (clamp ±0.1,
  пожизненный коридор ±0.6 от `traits_birth`) и весов (±0.05, коридор ±0.3
  от `weights_birth`), применение транзакционно (`SELECT … FOR UPDATE`) с
  discard при `died_at_tick IS NOT NULL` (сохранение narrative как
  «последняя мысль» в `world_events`, тип `last_thought`).
- `services/reflection-worker/tests/` — 7 файлов (при требовании минимум
  4): `queue.test.ts`, `validate.test.ts`, `apply.test.ts`,
  `integration.test.ts`, `degradation.test.ts`, `honesty.test.ts`,
  `metrics.test.ts` (последний — из фазы 7, не тронут).

### Дополнительно (не в списке артефактов, но необходимо для реальной работы)

- `services/reflection-worker/src/{constants,pool,types,db,age,request,
  prompt,worker,index,metrics}.ts` — вся оркестрация (обнаружение
  кандидатов из Postgres, сборка входа А.5 из реальных `creatures/episodes/
  bonds/aversions/signals`, цикл опроса с экспоненциальным бэкоффом).
- **Исправлен блокирующий пробел вне заявленного scope**: `episodes`
  никогда не писались в Postgres ни в одной предыдущей фазе (только
  in-memory). Без этого событийная рефлексия не могла бы сработать в
  реально работающем стеке. Добавлено `persist.ts::insertEpisodes` +
  буферизация в `Simulation` (`drainNewEpisodes`) — см.
  `ops/DEVIATIONS.md`, фаза 6, п.1.
- `persist.ts`: полный периодический снапшот sim-engine больше не
  перезаписывает 6 полей, которыми теперь владеет reflection-worker
  (`traits, weights, narrative, narrative_facts, intentions,
  last_reflection_at`) — иначе он стирал бы результат рефлексии в течение
  минуты (см. `ops/DEVIATIONS.md`, п.3).
- `Simulation.mockReflectionEnabled` — заглушка фазы 4 отключена в живом
  продакшн-процессе (`index.ts`), но остаётся для `npm run simulate --fast`.
- `docker-compose.yml`/`Dockerfile` reflection-worker: добавлены
  `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE` (отсутствовали — процесс не
  мог подключиться к БД вообще) и `COPY config` (constants.yaml не
  попадал в образ).

## Чем проверено

1. **`npm test` (корень, весь монорепо) → зелёный**: 29 файлов, 343 теста,
   включая всю новую директорию `services/reflection-worker/tests/` (42
   теста) — все против фейкового Anthropic-транспорта (`FakeAnthropicTransport`,
   реализует тот же интерфейс, что и боевой HTTP-клиент), реальный тестовый
   Postgres (эфемерный контейнер, как и у других сервисов).
   - `integration.test.ts`: 7 существ (3 событийных + 3 фоновых + 1
     "жертва"-участник эпизода), полный цикл episode → queue → anthropic
     (fake) → validate → apply → Postgres, включая проверку, что
     событийная рефлексия — по одному вызову на существо, а фоновая — ОДИН
     batch-вызов на все 3 сразу.
   - `degradation.test.ts`: API недоступен → очередь копится (`reflections`
     остаются `'queued'`), несколько часов сбоя не порождают дублирующих
     очередей на одно существо, экспоненциальный бэкофф проверен явно
     (попытка не повторяется раньше срока).
   - `honesty.test.ts`: сфабрикованное имя, отсутствующее в
     episodes/bonds/signals, проваливает валидацию и НЕ применяется;
     честный ответ проходит и каждый факт сверяется с реальным журналом
     `episodes`.
2. `npx tsc --noEmit` для `services/reflection-worker` и
   `services/sim-engine` (после правок persist.ts/simulation.ts/index.ts)
   — без ошибок.
3. `docker compose build` + `docker compose up -d` (весь стек, 8
   контейнеров) — поднимается без ошибок, включая рестарт `sim-engine`
   (восстановление из снапшота, без genesis) и `reflection-worker`
   (впервые с реальным кодом вместо заглушки фазы 1).
4. **Живой боевой прогон против реального Anthropic API** (см. ниже) —
   полный цикл эпизод → рефлексия → применённое изменение состояния
   существа проверен на настоящей работающей симуляции (сотни существ,
   тик продолжает идти), не только на тестовых фикстурах.

## Фактическая стоимость

**Тестовый прогон (`npm test`, фейковый транспорт): $0** — ни один тест не
обращается к сети/реальному API (см. `ops/DEVIATIONS.md`: причина — в этой
среде разработки нет надёжного способа изолировать реальные траты в CI;
логика транспорта подменяется на границе `AnthropicTransport`, весь
остальной код — реальный).

**Боевой прогон против реального API** (`ANTHROPIC_API_KEY` в `.env` этой
среды оказался рабочим ключом; мир к моменту прогона — ~130 живых существ,
тик ~3500-4200): в процессе живой отладки (несколько циклов
пересборки/рестарта `reflection-worker`, по мере обнаружения и исправления
реальных дефектов промпта/валидации — см. `ops/DEVIATIONS.md`, п.11)
потрачено:

| Источник | Модель | Вызовов (успешных) | Токены (вход/выход) | Стоимость |
|---|---|---|---|---|
| Batch (фоновая), batch `msgbatch_01CSVgRPs2ZSqv8xMLpts3AL` | Haiku 4.5 | 39 | 38 028 / 17 367 | $0.1249 |
| Batch (фоновая), batch `msgbatch_01LVVeu91kuJqw2Zna4FAEtE` | Haiku 4.5 | 23 | 32 652 / 10 977 | $0.0875 |
| Обычные вызовы (событийная), последний прогон (метрики) | Sonnet 5 | 7 | — | $0.0906 |
| Обычные вызовы (событийная/фоновая), более ранние прогоны до метрик выше (сброшены рестартом процесса, точные токены не сохранены) | оба | ~дюжина попыток/ретраев | — | не измерено точно, оценочно $0.05-0.15 |

Итого точно подтверждено Anthropic Batch API + текущими метриками
Prometheus: **≈ $0.30**; с учётом неизмеренных более ранних попыток —
реалистичная оценка всей сессии отладки **$0.35-0.45**. Это разовый всплеск
разбора НАКОПИВШЕГОСЯ backlog (весь мир сразу оказался "должен" рефлексию,
так как `reflections` были пусты) — при штатной работе (по расписанию 24ч/
4ч на существо) расход в разы ниже, в районе плановых `~$0.40/сутки` из
А.9/7.6. Итоговое состояние очереди на момент отчёта: событийная —
13 applied / 17 failed (провалили валидацию, не наврежены — discard, как и
задумано 7.3); фоновая — 19 applied / 44 failed (большинство `failed` —
из ПЕРВОГО прогона до исправления багов промпта, см. п.11 DEVIATIONS;
после исправлений процент успеха вырос заметно — второй batch (23 item)
дал 18-24 applied). Оба сервиса (`sim-engine`, `reflection-worker`)
оставлены работающими в docker-compose как штатное продолжение фазы —
это и есть переход в боевой режим, которого требует фаза 6.

Пример реально применённого результата (сокращённо, полный текст — в
`creatures.narrative` того существа):

> «Пими родила потомство — я видела это своими глазами. Что-то внутри
> дрогнуло... Теперь мне важнее быть рядом, оберегать лёд у гнезда...»
> narrative_facts: ["Стала свидетелем рождения потомства у Пими", "Состоит
> в парной связи с Пими", ...]; intentions: zone_bonus(main_ice)+0.3,
> approach_bonus(Пими)+0.4 — разрешено в реальный id через `bonds_summary`.

## Что не сделано (сознательно, зафиксировано в ops/DEVIATIONS.md)

- Живая (без рестарта) синхронизация `sim-engine`'s in-memory `Creature` с
  результатом reflection-worker — дрейф переживает рестарт процесса, но не
  влияет на решения ДО следующего рестарта (п.3).
- Персистентный (не in-memory) бэкофф ретраев — сбрасывается при рестарте
  воркера (п.10).
- Хранение `batch_id` между проходами — истёкший таймаут опроса создаёт
  НОВЫЙ batch вместо продолжения опроса старого (п.11).
- Генерация стартового self-narrative genesis-существа (6.1) — не входит
  в перечень задания фазы 6 (только фоновая+событийная), `reflections.kind
  = 'genesis'` зарезервирован в схеме на будущее (п.12).
- Полная семантическая проверка честности (7.8.6) — реализована
  механическая эвристика (грубое обнаружение выдуманных ИМЁН), не полная
  NLP-проверка утверждений (п.9).
- Промпт-кэширование не подтверждено эффективным для Batch API-ветки в
  этом прогоне (`cache_creation/read_input_tokens = 0` у всех элементов
  одного batch) — не решено офлайн без документации, стоимость уже мала и
  без кэша (п.11).
