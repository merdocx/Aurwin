# Отчёт по фазе 5 «Наблюдение»

Дата: 2026-07-31

Работа продолжает прерванную по лимиту ходов предыдущую попытку (WIP-коммит
`5af24c1`). При ревизии выяснилось, что и `services/api-gateway/`, и
`apps/frontend/` уже содержали рабочую реализацию всей фазы — доделывать
код не потребовалось; эта сессия состояла из проверки (тесты, сборка,
`docker compose up`, живой прогон против реальной симуляции) и написания
этого отчёта.

## Что сделано (api-gateway, `services/api-gateway/`)

- **WebSocket `/ws`** (`ws.ts`): `snapshot` при подключении (все живые
  существа + зоны + текущие тик/фаза), `delta` каждый `time.
  visual_tick_seconds` (2 сек) — легковесный DTO (`id, species, name, x, y,
  zone, emotion, is_asleep, age_band`) + `world_events` с прошлого
  разосланного тика. Фильтрация по видимой области — `inViewport()` в
  памяти процесса, один общий запрос к БД на тик независимо от числа
  клиентов. `viewport` от клиента — первое/повторное сообщение `{type:
  "viewport", x, y, width, height}`; до его получения отдаётся вся карта.
  Ускоряющий `LISTEN world_tick` (Postgres NOTIFY от sim-engine) — таймер
  `visual_tick_seconds` остаётся резервным ритмом на случай, если LISTEN не
  подключился.
- **REST** (`rest.ts`, `server.ts`): `GET /api/creatures/{id}` (карточка:
  имя, вид, пол, возраст в неделях, черты, потребности, эмоция, сон,
  ведущие 3 навыка, `narrative_facts`, лента до 30 событий), `GET
  /api/social-graph` (узлы + рёбра `kind = 'friend'`, кэш 10 сек), `GET
  /api/world/stats` (тик, фаза, население по видам, поколение). Только
  `GET`, всё остальное — 405.
- **Запрет `narrative`**: гарантирован структурно, не только фильтрацией
  ответа — `queries.ts` (единственное место, откуда api-gateway читает
  `creatures`) ни в одном SELECT не перечисляет колонку `narrative`, поэтому
  утечка возможна только через саму БД, а не через код gateway.
- **Лимиты (А.6)**: `RestRateLimiter` — 60 REST-запросов/мин/IP (429 +
  `retry-after`), периодическая уборка окон. `WsConnectionLimiter` — 3
  одновременных WS-соединения/IP, graceful-отказ 4-му (`close(1013, "over
  capacity")` с сообщением `{"type":"error", ...}` перед закрытием, вместо
  падения процесса) + отдельный лимит общего числа соединений сервера.
  `social_graph_cache_seconds: 10` — in-memory кэш ответа.
- Все числа лимитов — в `config/constants.yaml` (секция `api`), не
  захардкожены (обоснование добавления вне табл. А.9 — как в фазах 2-4, см.
  `ops/DEVIATIONS.md`, пункт добавлен в этой фазе см. ниже).

## Что сделано (фронтенд, `apps/frontend/`, React + PixiJS)

- **`WorldStore`** (`ws/WorldStore.ts`) — состояние мира вне React;
  `getRenderState(now)` линейно интерполирует позицию каждого существа между
  `prevX/Y` и `targetX/Y` за время `tickSeconds` — движение не дёргается
  между дельтами, приходящими раз в 1-2 сек, отрисовка идёт на полном FPS
  тикера PixiJS.
- **`PixiWorld`** (`render/PixiWorld.tsx`): зоны отрисованы один раз (лёд/
  вода), тело существа — интерполированная позиция + цвет по виду; ночной
  оверлей (`nightOverlay`, альфа плавно сходится к 0.6 ночью / 0 днём —
  `NIGHT_TRANSITION_RATE`) делает смену дня/ночи явной, но не резкой; спящие
  — приглушённая заливка (alpha 0.55) + метка «z»; индикатор эмоции — точка
  над телом, цвет от валентности, размер от возбуждения; события
  (`alarm_call`/`display_vigor`/сигналы — расширяющееся цветное кольцо;
  смерть/охота — расходящееся белое облако, без натурализма) гаснут за 2.5
  сек. Навигация — только перетаскивание (пан) и колесо (зум 0.15×–3×);
  клик по существу открывает карточку. Никаких других действий клиенту не
  доступно.
- **`CreatureCard`** (`components/CreatureCard.tsx`): имя, вид, пол,
  возраст, причина смерти (если умер(ла)), черты (полосы), 3 ведущих
  навыка, состояние (сон/бодрствование, настроение, голод, усталость),
  `narrative_facts` (без `narrative`), лента до 30 событий с человекочитаемыми
  подписями по-русски.
- **`SocialGraph`** (`components/SocialGraph.tsx`): круговая раскладка
  узлов, рёбра — толщина/прозрачность по `strength`, клик по узлу открывает
  карточку существа.
- **`useWorldSocket`**: авто-переподключение при разрыве (мир не зависит от
  наблюдателя — 6.1), throttle отправки viewport (400 мс), обработка
  серверного `{"type":"error"}` (статус "отказано" в HUD при перегрузке).

## Чем проверено (гейт фазы 5)

1. `npm test` (корень, весь монорепо) → **зелёный**: `Test Files 18 passed
   (18)`, `Tests 287 passed (287)`, включая
   `services/api-gateway/tests/gateway.test.ts` (6 тестов):
   - `narrative` отсутствует в `/api/creatures/{id}`, `/api/social-graph`,
     `/api/world/stats` (рекурсивный поиск ключа `"narrative"` по всему
     JSON-ответу, плюс поиск секретной строки-маркера в сыром тексте ответа);
   - несуществующий id → 404, не 500;
   - 60 REST-запросов/мин с IP разрешены, 61-й → 429;
   - 3 одновременных WS-соединения с IP открываются, 4-е получает
     graceful-отказ (`close code 1013`).
2. `npx tsc --noEmit` для `services/api-gateway` и `apps/frontend` → без
   ошибок; `npm run build --workspace=@aurwin/api-gateway` → компилируется.
3. `docker compose build api-gateway frontend` и `docker compose up -d` →
   все 5 контейнеров (`postgres`, `sim-engine`, `reflection-worker`,
   `api-gateway`, `frontend`) в состоянии `Running`/`Up`, без падений и
   рестартов; логи чистые (`api-gateway` слушает порт 3000,
   `frontend`/Vite поднялся на 5173).
4. **Живой прогон против реальной работающей симуляции** (не только
   тестовая БД): `GET /api/world/stats` → `{"tick":976,"phase":"day",
   "population":{"penguin":85,"orca":10},"generation":1}`; `GET
   /api/social-graph` вернул реальных существ с именами; `GET
   /api/creatures/{id}` для случайного живого пингвина вернул полную
   карточку (черты, потребности, эмоция, `is_asleep: true`, ведущие навыки,
   пустые пока `narrative_facts`/`timeline` — существу 5 недель) **без
   единого ключа `narrative`** — проверено вручную по сырому JSON.
5. **Не проверено визуально в браузере** — в этой среде недоступен
   инструмент со скриншотом/DOM браузера (нет Playwright/аналога,
   попытка `npx playwright` требует установки пакета, которая недоступна
   офлайн). Проверено то, что доступно без браузера: TS собирается без
   ошибок, `vite`-сервер отдаёт корректный HTML/JS на `GET /`, вся логика
   рендера (интерполяция, ночной оверлей, метка сна, кольца событий)
   прочитана построчно и соответствует гейту по коду. Визуальную приёмку
   (действительно ли ночь "заметно" темнее, не наслаиваются ли элементы
   HUD) стоит сделать вручную в браузере разработчиком перед мёрджем —
   явно фиксирую как непроверенное, а не выдаю за подтверждённое.

## Что не сделано (сознательно, вне рамок фазы 5)

- Восстановление live-состояния `sim-engine` из БД после рестарта — уже
  зафиксировано как открытый пункт в `ops/DEVIATIONS.md` (фаза 4), не
  входит в фазу 5.
- Масштабирование gateway на несколько инстансов (лимитеры — in-memory на
  процесс) — вне рамок MVP (7.5, "не жёсткое требование").
- Реальные LLM-вызовы (рефлексия) — по-прежнему замокана, боевые вызовы
  запрещены до фазы 6 (CLAUDE.md, п.7).
