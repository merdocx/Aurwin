# Aurwin — контекст проекта

Полное ТЗ: docs/AURWIN_TZ.md. Читай его перед любой задачей.
При конфликте твоего решения с ТЗ — прав ТЗ; расхождения фиксируй в ops/DEVIATIONS.md.

## Незыблемые правила
1. Никогда не коммить .env и любые ключи. Секреты читать только из окружения.
2. Ключ Anthropic не должен попадать во фронтенд-код ни в каком виде.
3. Все константы симуляции — только в config/constants.yaml по таблице А.9.
   Не хардкодить числа в коде.
4. Не менять значения констант «чтобы тест прошёл». Тест не проходит — чинить логику
   или писать в ops/DEVIATIONS.md с обоснованием.
5. Симуляция никогда не блокируется на LLM-вызове (раздел 7.3).
6. Не удалять и не пересоздавать БД без явного указания. Данные мира — ценность.
7. Не запускать боевую симуляцию с реальными LLM-вызовами до фазы 6.
   До этого рефлексия только замокана.
8. Действия «обмануть» не существует. Сигнал — обычное действие; ложность
   вычисляется постфактум как расхождение true_state и claimed_state (7.8).
9. Численность популяции — не настраиваемый параметр. Не устраивает численность —
   меняй ёмкость среды (респавн рыбы, летальность охоты), а не число особей (7.4).

## Стек (раздел 7.5)
Node.js/TypeScript, PostgreSQL, WebSocket, React + PixiJS, docker-compose.

## Определение готовности фазы
Фаза завершена, когда `npm test` зелёный, `docker compose up` поднимается без ошибок,
и в ops/reports/phase-N.md записано: что сделано, что не сделано, чем проверено.
